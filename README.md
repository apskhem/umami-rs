# umami-rs server

A headless Rust backend that is a drop-in replacement for [Umami](https://umami.is)
**v3.4.1** on PostgreSQL: same database schema, same JSON API, so existing Umami
databases, the official tracker script and the official dashboard work against it.

## Layout

| Crate | Purpose |
|---|---|
| `umami-db` | Connection handling and the migrator. `migrations/` is a verbatim copy of upstream's Prisma migrations, applied with Prisma's `_prisma_migrations` bookkeeping so upstream and umami-rs can migrate the same database interchangeably. |
| `umami-server` | The axum HTTP server (`umami-server` binary). |
| `tools/tracker` | Fetches upstream's built tracker script (`umami-server/assets/script.js`) from its release image. |
| `tools/ua-rules` | Generates the server's user-agent rule tables and parity fixtures from the JS libraries upstream uses. |

## Running

```sh
docker compose up -d          # local Postgres
cp .env.example .env
cargo run -p umami-server
curl localhost:3000/api/heartbeat   # {"ok":true}
```

On startup the server checks the Postgres version and applies pending migrations, as
upstream's `check-db` script does. A fresh database gets upstream's default login,
`admin` / `umami`.

## Event collection

`POST /api/send` and `POST /api/batch` accept the official tracker's payloads and
write the same rows upstream does: session and visit IDs, cache tokens, UTM and
click-ID parsing, custom event data, revenue, `identify` and web-vitals events.

- **Geolocation** comes from CDN headers (Cloudflare, Vercel, CloudFront, EdgeOne)
  or a MaxMind GeoLite2 City database at `geo/GeoLite2-City.mmdb` (or
  `GEOLITE_DB_PATH`). Without a database the server still runs and relies on headers.
- **User agents** are classified by Rust ports of `detect-browser`, `isbot` and
  `ua-parser-js`, generated by `tools/ua-rules` and tested against those libraries
  on ~2,300 real user agents. Device types come from ua-parser-js 1.x (MIT): upstream
  uses 2.x, which is AGPL-licensed, and the two disagree on under 1% of the corpus.
- Session and visit periods are computed in UTC (upstream uses the server's time
  zone, which is UTC in its Docker image).

To update the user-agent rules after an upstream bump, change the versions in
`tools/ua-rules/package.json`, then:

```sh
cd tools/ua-rules && npm ci --ignore-scripts && npm run generate && npm run fixtures
```

## Tracker script

`/script.js` serves upstream's tracker exactly as the v3.4.1 release image ships it,
with the same caching and CORS headers; `TRACKER_SCRIPT_NAME` adds alias paths and
`COLLECT_API_ENDPOINT` re-points the script, as upstream does at startup. Embed it
as with upstream:

```html
<script defer src="https://analytics.example.com/script.js" data-website-id="..."></script>
```

To track a newer upstream release, run `python3 tools/tracker/fetch.py <version>`
and update `SCRIPT_SHA256` in `umami-server/src/tracker.rs`.

Not supported: `TRACKER_SCRIPT_URL` (proxying the script from elsewhere),
`COLLECT_API_HOST` (a build-time option upstream; use `data-host-url` instead) and
the session-replay `recorder.js`.

## Configuration

Environment variables follow upstream where an equivalent exists; see `.env.example`.
`HOST` replaces upstream's `HOSTNAME`, which Docker sets to the container ID.

## Tests

```sh
cargo test                                   # unit + HTTP tests, no database needed
TEST_DATABASE_URL=postgresql://umami:umami@localhost:5432/umami \
  cargo test -- --include-ignored            # also run database tests
```
